# Passkey 使用与部署

[English](passkey.en.md) | 简体中文

Passkey 默认关闭。配置入口为 **面板设置 → 安全 → Passkeys（通行密钥）**。

先保留可用的管理员密码；添加凭证、撤销凭证或保存登录配置时，需要当前密码，已开启 TOTP 的账号还需验证码。Passkey 登录要求设备验证（指纹、面容或 PIN），无需填写用户名、密码和 TOTP。密码登录仍遵守原有 TOTP 设置。

## 启用

1. 通过对外 HTTPS 域名访问面板，例如 `https://panel.example.com:8443/secret/`。
2. 设置站点域名为 `panel.example.com`；允许访问地址填 `https://panel.example.com:8443`。不填 `/secret/`，不使用 IP、通配符、父域范围或 HTTP。每行一个地址，最多 16 项；所有地址必须是同一个确切域名。
3. 选择 HTTPS 部署方式。直连模式要求面板已配置可加载的证书和私钥，并且浏览器实际通过 TLS 连接面板。反代模式要求代理保留原始 Host，并配置可信代理地址。
4. 打开功能开关，点击“检查配置”。这只校验格式和当前访问地址，不测试真实设备、证书或代理部署。
5. 点击“保存 Passkey 配置”，确认影响并输入密码/TOTP。成功后所有旧浏览器会话失效；用密码重新登录。Passkey 配置即时生效，不需要使用其他标签页的全局保存。
6. 点击“添加 Passkey”，填写可识别的设备名称并再认证，在浏览器/系统提示中完成验证。建议再添加一个备用设备，每个账号最多 10 个。
7. 退出后，在登录页点击“使用通行密钥登录”，选择已登记的凭证。浏览器不支持或当前地址未获允许时，使用密码登录。

## 反向代理

“可信代理地址”复用既有公共 Web 设置，影响客户端 IP、登录限流和 HTTPS Cookie。默认值为 `127.0.0.1/32,::1/128`；填写实际代理地址或受控网段。支持 IPv4、IPv6、CIDR，禁止 `0.0.0.0/0`、`::/0` 和空反代列表。

以下是代理相关指令示例，应合并到已有 Nginx 配置中。代理须覆盖客户端传入的转发头；后端端口应只允许代理访问。

```nginx
location /secret/ {
    proxy_pass http://127.0.0.1:2053;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $remote_addr;
}
```

仅从可信代理接收 `X-Forwarded-Proto: https`。对外非默认端口要保留在 Host 和允许访问地址中。多层代理需按实际拓扑设计可信地址和客户端 IP 传递，不能直接信任客户端提供的头。

## 撤销与恢复

- 改名只影响显示。撤销需要密码/TOTP，成功后该账号所有浏览器会话失效。
- 关闭功能保留凭证，阻止注册和登录。改变站点域名保留旧域名记录供查看和删除，必须在新域名重新登记。
- 更改或重置管理员密码会撤销该账号全部 Passkey。服务端撤销不会删除系统密码管理器中的记录，必要时另行清理。
- 本地恢复命令：管理脚本 `x-ui reset-passkeys`；直接调用二进制 `/usr/local/x-ui/x-ui setting -resetPasskeys=true`。目标为数据库中的第一个管理员，命令遵守已有数据库环境配置。
- CLI 重置 TOTP 会使旧会话和待完成的授权失效，同时保留 Passkey 凭证。

完整备份包含 Passkey 配置、用户映射和凭证公钥数据，不包含设备私钥和临时挑战。完整恢复会随机刷新会话 epoch 和配置版本。恢复旧备份可能重新带回后来撤销的凭证；有泄露疑虑时，在恢复后本地撤销全部 Passkey。

“保留本机设置”的导入保留本机 Passkey 配置和代理设置，但删除导入的用户映射及凭证，防止不同数据库的用户 ID 重用导致凭证转移；导入后重新绑定。

替换数据库前会在数据库目录创建 `<数据库名>.db.auth-restore` 恢复记录，并暂停新面板请求。认证状态刷新成功后才恢复服务并删除记录。如果导入失败或进程中断，重启面板会先按记录重新处理认证状态；处理失败时面板不会开放 HTTP 服务。记录损坏时应保留现场、修复数据库或恢复记录，不能通过直接删除记录来绕过保护。中断的“保留本机设置”导入仍会清理凭证，需要用密码登录后重新绑定；目录需允许服务账号创建、同步和删除该文件。

## 验证与限制

当前支持单面板实例；挑战保存在有上限的内存中，120 秒过期并原子消费，重启后需重新发起操作。管理授权 5 分钟内单次有效。取消设备提示通常不构成服务端验证失败；尚未完成的挑战会自动过期。

LDAP 作为现有本地账号的密码认证后备；Passkey 绑定本地账号，不实时查询 LDAP 状态。要求目录停用即时阻断登录的部署应保持此功能关闭。

开发验证：

```powershell
npm --prefix frontend run build
$env:XUI_PASSKEY_BROWSER_TEST = '1'
go test ./internal/web/controller -run '^TestPasskeyBrowser$' -count=1 -v
```

浏览器验证需要已安装的 Playwright Chromium，使用独立临时数据库，不修改运行中的面板。生成的桌面和移动端截图位于 `.cache/passkey-browser/`。本地签名和虚拟认证器检查已通过；真实设备、可信反代和真实 PostgreSQL 不属于本地测试已证明的范围。
